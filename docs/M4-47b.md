## 1. IPI 投递：三个里程碑的悬案结案

**症状**：`[tlb] ACK TIMEOUT ack=0 want=3`，AP 从未响应过任何硬件 IPI；
0xFE 唤醒、0xFD/0x30 shootdown 全部"收不到"，只能靠 AP timer + 轮询兜底。

**根因**：x2APIC ICR（MSR 0x830）的 **Delivery Status（Bit 12）**。
上一次发送仍处于 pending 时，写 ICR 的新 IPI 会被硬件**静默丢弃**——
不报错、不重试、ESR 也不一定置位。

**修复**（arch/x86_64/lapic.c）：
1. 写 ICR **之前**先轮询等 Bit 12 清零（排空上一次发送）；
2. 写之后等待完成；
3. 读 IA32_X2APIC_ESR（0x828）并在非 0 时打印 + 写 1 清除。

**实证**：
- `[smp] IPI probe: irq 3 -> 4 (expect +1)` —— 一次性硬件 IPI 探针，AP 侧计数真实 +1；
- 10 轮连续运行 `ACK TIMEOUT = 0`（修复前每轮 26 次）；
- SVR=0x1FF（APIC enable 置位）、TPR=0、AP 均调用 `lapic_init()`——先前的使能位嫌疑全部排除。

## 2. wait 丢失唤醒窗口原子化

**症状**：父进程 `SYS_WAIT` 扫描"无 ZOMBIE" → 子进程恰好退出并 `task_wakeup(parent)`
（此时 parent 仍 RUNNING，唤醒被丢弃）→ parent 置 `TASK_WAITING` 并睡眠，永不醒来。

**修复**：
- `sched/scheduler.c` 新增 `task_wait_enter()/task_wait_leave()`，复用 `run_queue_lock`
  作为"检查子进程 + 置 WAITING"与"置 ZOMBIE + 唤醒 parent"的公共临界区；
- 退出路径的状态迁移与 stop 路径的 `TASK_STOPPED` 迁移同样放进该临界区；
- `SYS_WAIT`/`SYS_WAITPID` 改为持锁检查：有僵尸→**先解锁**再 `copy_to_user`/`task_reap`
  （`task_reap` 自身会拿 `run_queue_lock`，锁内调用会自死锁）。

## 3. wake IPI 处理器不得在 ISR 内调度

IPI 真正能投递之后，`SMP_WAKE_VEC` 处理器里的 `schedule()` 才第一次被实际执行——
在中断上下文里嵌套调度会破坏 AP 的切换现场。改为**只 EOI**（AP idle 本就轮询
`schedule()`，唤醒语义不变）。
