# M4-47d — TLB 活锁、串口丢字、堆护栏：三案并破

> 状态：**已提交**；fresh-disk `make test` **10/10**，三时序档位全绿
> 日期：2026-11-01

## 1. TLB shootdown 活锁（GDB 当场击毙）

`-icount shift=7` 下 3/3 必现于 tick=100，GDB 四核同框：

```
CPU0/1/2/3 全部: tlb_shootdown_all+162 (ack 自旋, tlb.c:40)
栈: SYS_WAIT -> task_reap -> task_finish_reap -> tlb_shootdown_all
tlb_ack_count=0，五把锁全部 locked=0
```

不是 ABBA 死锁，是**活锁**：syscall 经中断门进内核时 IF=0，正在自旋等 ACK
的 CPU 永远无法响应同侪发来的 shootdown IPI；全局单例 ack 计数又被每个
进入的 reaper 清零。修复：`tlb_shootdown_all` 改为 fire-and-forget——
`task_finish_reap` 只在 `active_cpus==0` 时执行，已无任何核在执行该地址
空间，后续任何核 CR3 写入即硬件刷新；IPI 仍然发送（使能中断的对端可提前
重载）。实测 icount 档从 100 tick 卡死到连续运行 **290+ 虚拟秒**。

## 2. 串口丢字（"测试脚本瞎了眼"案）

M4-47c 后多轮 "stress=2/1 的 FAIL" 尸检：三个 worker 全部 `exit status=0`
（即都打印过 PASS）、A/B 心跳直到 40s 超时、全部 marker 存在——**内核活着，
串口丢字**。两处根因：

- `uart_putc` 的 1e6 忙等超时**静默丢弃**字符（THR 忙时直接 return）；
- 内核 kprintf 与用户 console_write 是两条独立通道，行级交织撕裂 marker。

修复：`uart_putc` 无界等待 THRE + `uart_lock` 跨核串行；新增 `uart_puts`
整缓冲一次持锁；console_write 改走 `uart_puts`。所谓"tick 2500 晚期冻结"
被证明是同一观测假象——无残留冻结。

## 3. 堆护栏 + 操作环形日志（取证装备，常驻）

`find_free_block` 加 10 万步扫描护栏；`kmalloc`/`kfree` 记录最近 64 次
操作调用者 RIP；触发时裸串口 dump（绕 kprintf 锁）。实测冻结轮 heap 打印
为 0 —— 用排除法将堆子系统无罪释放，装备留在主线待命。
